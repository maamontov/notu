# notu

```text
┌┬─┐ ┐ ┌┬──┐ ┌─┬┬─┐ ┌┐  ┐
├┤ │ │ ├┤  │   ├┤   ├┤  │
└┘ └─┘ └┴──┘   └┘   └┴──┘
```

**Лёгкие, локальные Markdown-заметки прямо в терминале.**

notu — TUI-приложение на Rust для быстрых записей, ежедневных заметок и небольших
проектов. Один исполняемый файл, привычные `.md` и управление с клавиатуры.

## Почему notu

- **Лёгкое.** Один компактный бинарник. В простое приложение ждёт события терминала
  и не расходует CPU на постоянный опрос или перерисовку.
- **Локальное.** Заметки и настройки находятся на вашем компьютере. Приложение
  работает офлайн; аккаунт, сервер и подключение к облаку не нужны.
- **Открытый формат.** Обычные UTF-8 файлы `.md`: их можно читать другими редакторами,
  хранить в Git и синхронизировать выбранным способом.
- **Быстрые действия.** Создание сегодняшней заметки, поиск, переименование
  и переход между списком, редактором и Markdown-превью — с клавиатуры.
- **Обратимые действия.** Подтверждение удаления, локальный архив и восстановление
  с защитой от перезаписи существующих заметок.

## Возможности

- Редактор исходного Markdown и отдельное форматированное превью.
- Ежедневная заметка `daily: DD-MM-YYYY` одной командой.
- Поиск по названиям и тегам с совместными фильтрами.
- Поиск внутри текущей заметки: подсветка, количество совпадений и переходы по кругу.
- Цветные теги в списке и заголовке заметки.
- Группировка по дате создания и полосы прокрутки.
- Запоминание курсора и позиции просмотра при переключении заметок в текущем сеансе.
- Автоматическое сохранение при возврате к списку, переключении заметок и выходе.
- Выбор основного цвета и настройка цветов тегов.
- Адаптивная ширина панелей, постоянный индикатор режима и перенос подсказок.
- Прокручиваемая справка `F1`.

## Установка

Для сборки нужен **Rust 1.88+**. Готовому бинарнику Rust не нужен.

```sh
git clone https://github.com/maamontov/notu.git
cd notu
cargo build --release --locked
./target/release/notu
```

Для установки команды в `PATH`:

```sh
cargo install --path . --locked
notu
```

Бинарник можно переносить отдельно. Он должен соответствовать ОС и архитектуре
компьютера, на котором будет запускаться.

## Быстрый старт

```sh
notu                               # открыть список заметок
notu --today                       # сразу открыть заметку на сегодня
notu --workspace ~/Documents/work  # выбрать каталог
notu --help
```

По умолчанию workspace создаётся в системном каталоге документов:
`Documents/notu`. На Linux учитывается XDG Documents; если системный каталог
не определён, используется `~/Documents/notu`.

Путь можно задать через `NOTU_WORKSPACE`. Аргумент `--workspace` имеет приоритет.
Для работы нужен интерактивный терминал. Для удобного размещения обеих панелей
и всех подсказок используйте окно от **40×14**, предпочтительно **80×24** и больше.

```text
Documents/notu/
├── daily: 30-09-2026.md
├── work: Архитектура.md
├── Идеи.md
├── .notu.json
├── .notu-created.json
└── .notu-trash/
```

Название заметки берётся из имени файла и независимо от Markdown-текста.
Новая заметка всегда создаётся с пустым содержимым.

## Управление

Основные сочетания одинаковы во всех режимах. В нижних подсказках `^` означает `Ctrl`.
Индикатор `LIST` / `EDIT` / `PREVIEW` показывает текущий режим; активная рамка
выделяется основным цветом. Подсказки переносятся на несколько строк при уменьшении
окна и остаются в одном месте.

| Клавиши | Действие |
| --- | --- |
| `Ctrl+N` | Новая заметка |
| `Ctrl+D` | Создать или открыть сегодняшнюю заметку |
| `Ctrl+S` | Сохранить текст; в настройках — применить изменения |
| `Ctrl+F` | Поиск по названиям |
| `Ctrl+T` | Фильтр по тегу |
| `Ctrl+G` | Поиск внутри текущей заметки |
| `Ctrl+R` | Перечитать workspace после внешних изменений |
| `Ctrl+Q` | Сохранить и выйти |
| `F1` | Справка |
| `F2` | Список / редактор |
| `F3`, `Ctrl+P` | Markdown-превью / редактор |
| `F4` | Настройки основного цвета |
| `F5` | Переименование |
| `F6` | Настройки тегов |
| `F7` | Подтверждение удаления |
| `F8` | Восстановить последнюю удалённую заметку |
| `F9` / `F10` | Следующее / предыдущее совпадение в тексте |

В списке `↑` / `↓` или `j` / `k` выбирают заметку, `Enter` включает редактор.
`Esc` или `F2` в редакторе и превью сохраняют правки и возвращают полный список.

В редакторе доступны стрелки, `Home` / `End`, `PageUp` / `PageDown`, выделение
через `Shift` + стрелки, отмена / повтор через `Ctrl+Z` / `Ctrl+Y` и внутренний
буфер `Ctrl+X` / `Ctrl+C` / `Ctrl+V`. Для вставки из системного буфера используйте
сочетание терминала, например `Ctrl+Shift+V` или `Cmd+V`. Многострочная вставка
поддерживается через bracketed paste.

В полях создания, переименования, поиска и имени тега тоже работают курсор,
`Home` / `End`, выделение, вставка и отмена. Для создания и переименования
`Enter` или `Ctrl+S` подтверждают действие, `Esc` отменяет.

В превью и справке работают `↑` / `↓`, `PageUp` / `PageDown`, `Home` / `End`.
Страница прокручивается на высоту видимой области. `Esc` закрывает справку.

## Поиск

**По названиям:** `Ctrl+F`, введите часть названия. Результаты обновляются сразу;
`↑` / `↓` выбирают заметку, `Enter` закрывает ввод и оставляет отфильтрованный список.

**По тегам:** `Ctrl+T`, введите тег или его часть. Фильтр учитывает только префикс
до первого `:`. Его можно совместить с поиском по названию: например, выбрать
`work`, затем найти `релиз`. Активные фильтры отображаются над списком.
`Esc` в поиске или списке очищает оба фильтра.

**Внутри заметки:** `Ctrl+G`, введите текст и нажмите `Enter`. Поиск работает
в исходном Markdown, включая несохранённые правки, без изменения содержимого.
Регистр не учитывается; символы вроде `[` и `*` ищутся буквально.
Совпадения подсвечиваются; `F9` и `F10` переходят вперёд и назад с возвратом
к началу или концу. `Esc` в поле поиска очищает подсветку и возвращает прежнюю
позицию курсора. Поиск внутри заметки не ищет сразу по всем файлам.

## Ежедневные заметки и теги

`Ctrl+D` и `--today` используют **локальную дату компьютера** и создают
`daily: DD-MM-YYYY.md`. Повторное действие открывает тот же файл, сохраняя его текст.
Сегодняшний файл старого формата `YYYY-MM-DD.md` автоматически переименовывается,
если файл с новым именем ещё не существует.

В названии `work: План релиза` префикс `work` — тег. Цвет можно выбрать через `F6`:
`+ New tag` → имя → цвет → `Enter`. `Ctrl+S` применяет весь набор настроек;
`Esc` отменяет текущий диалог, а на основной странице — весь черновик.
Создание тега завершается только после подтверждения цвета.

`Enter` на существующем теге меняет цвет, `Delete` удаляет настройку цвета,
сохраняя заметки. Встроенный `daily` удалить нельзя; его цвет менять можно.
Имена тегов для настройки цвета учитывают регистр, поиск по тегам — нет.
Не настроенные теги тоже доступны для поиска.

`F4` выбирает основной цвет: Cyan, Blue, Green, Magenta, Yellow, Red или White.
Настройки сохраняются отдельно для каждого workspace.

На Linux и macOS двоеточие хранится буквально в имени файла. В Windows такие
имена запрещены: обычные заметки доступны, но формат тегов и `daily:` там пока
не поддерживаются.

## Удаление и восстановление

`F7` показывает имя файла и предлагает `Cancel` по умолчанию.
`Esc`, `N` или `Enter` на `Cancel` отменяют действие. `Y` либо выбор `Delete`
стрелками / `Tab` с последующим `Enter` подтверждает удаление.
Переход в другой режим отменяет незавершённое подтверждение.

Перед удалением создаётся локальная копия в `.notu-trash/`. `F8` восстанавливает
последнюю удалённую заметку вместе с текстом и датой создания; повторные нажатия
восстанавливают более ранние удаления. Это работает и после перезапуска.
Существующие имена не перезаписываются: сначала переименуйте файл, мешающий
восстановлению. Архив хранится до восстановления или ручного удаления его папки.

## Сохранение и надёжность

Запись текста выполняется через временный файл в том же каталоге с атомарной
заменой. `*` рядом с заголовком означает несохранённые правки.
Фонового сохранения по таймеру нет; при аварийном закрытии несохранённый текст
может быть потерян.

Перед записью и удалением notu проверяет внешние изменения. При конфликте правки
остаются в редакторе; `Ctrl+N` позволяет сохранить копию под новым именем.
Проверка защищает от обнаруженных конфликтов, но не блокирует файл для других
процессов. Символические ссылки на заметки не открываются.

Даты создания хранятся в `.notu-created.json`, настройки — в `.notu.json`.
Повреждённый JSON сохраняется в файл `.corrupt-…`, затем служебные данные
восстанавливаются; сами `.md` не меняются. Настройки возвращаются к значениям
по умолчанию, даты восстанавливаются из доступных метаданных файловой системы.
Предупреждение показывается внизу; полное сообщение доступно в конце справки `F1`.

Список читает только имена и метаданные файлов непосредственно в workspace,
без обхода вложенных каталогов. Markdown разбирается при открытии просмотра,
результат кешируется. Содержимое открытой заметки хранится в памяти.

Превью поддерживает заголовки, **жирный**, *курсив*, зачёркивание, списки,
задачи, цитаты, ссылки, блоки кода и таблицы. Изображения отображаются текстом;
HTML не исполняется, подсветки языков программирования пока нет.

## Разработка

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --release --locked
```

- `src/app.rs` — состояния интерфейса, клавиши, поиск и отрисовка.
- `src/store.rs` — файлы, даты создания, сохранение и архив удалений.
- `src/config.rs` — настройки и цвета тегов.
- `src/recovery.rs` — резервные копии повреждённых служебных файлов.
- `src/main.rs` — аргументы запуска и жизненный цикл терминала.
